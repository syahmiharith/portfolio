## The problem

A receipt photo preserves the evidence, but someone still has to turn it into fields and correct transcription mistakes. Receipt-to-Form gives that review a place in the workflow.

## My role

Receipt review, validation and dependency maintenance. The repository retains the earlier project attribution.

## Decisions

### Keep the image beside the correction

The review interface places the receipt beside editable fields. A person checking a total should be able to compare it with the source without switching contexts. The repository documents this review path; the portfolio capture shows the upload entry.

### Treat missing data as missing

A missing amount stays null. Normalization turns absent provider fields into a low-confidence draft with review notes, rather than inventing a complete record. The schema tests also reject malformed line items.

### Separate model variability from regression checks

Mocked extraction tests make interface and validation failures reproducible. A live extraction check answers a different question: whether the deployed model integration works. Passing one does not substitute for the other.

## Maintaining the data contract

A dependency update moved validation from Zod 3 to Zod 4. The same change added regression cases for nullable line items, omitted quantities, invalid values and unexpected provider fields. Updating the library included checking the receipt data it accepts and rejects.
