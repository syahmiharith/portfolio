## Receipts in. Expenses ready.

A receipt is the starting point. The useful result is an expense record someone can check, correct, and put straight into a spreadsheet.

I built Receipt-to-Form around that complete task: capture the details, compare them with the image, approve the values, and export a CSV that matches the review. The product keeps each receipt and its corrections in one place from upload to download.

## What I designed and built

I designed and built the receipt editor, saved revisions, review model, interruption recovery, and receipt-level CSV export. I own the workflow across the interface, extraction integration, persistence, and release verification.

The implementation uses Next.js, React and TypeScript, with IndexedDB for browser recovery and shared Redis limits for live extraction.

## Design decisions

### Put the receipt beside the decision

On desktop, the image sits beside editable expense fields. On smaller screens, a keyboard-accessible switch moves between image and form. Zoom and rotation help the preparer inspect the source without leaving the task.

Each receipt carries its own save, discard and review actions. One batch toolbar handles selection and export. Samples and uploaded receipts use that same workflow.

### Export the values the preparer approved

I made review apply to a saved revision. Editing blocks export immediately. Save commits the correction; Mark reviewed approves it; Discard restores the saved values and their review status.

CSV uses that reviewed revision. Dates, currency and decimal totals are validated before approval. Receipt IDs and filenames preserve the path back to the source, while original extraction and model confidence remain separate from human changes.

### Let interrupted work continue

Versioned browser storage retains images, pending edits, saved revisions and review state. Refresh returns to the same work. Interrupted requests remain manually retryable, and a mixed batch keeps the receipts that succeeded.

I designed loading, validation, retry, stopping, storage recovery and image-error states around the next useful action. The preparer can keep moving through the task.

## What I own after launch

I own the release path as well as the screen. I maintain extraction limits, safe spreadsheet output, browser recovery, keyboard access and regression coverage as parts of the same product.

I improved keyboard image inspection across browsers with explicit arrow-key panning, added a regression that uses actual keys, and verified the update on the live product.

## A complete workflow, checked in production

The decisive regression edits an already-reviewed total, blocks its export, refreshes with the correction pending, then saves and reviews it again. The downloaded CSV is checked against that approved value and the original receipt ID. JSON retains the original confidence.

I also verify the deployed sample journey and real receipt extraction through an inspected CSV. That makes the live product, the interaction decisions and the maintained implementation available to explore together.
